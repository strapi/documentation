# TypeScript configuration

<Tldr>
TypeScript configuration explains the project’s tsconfig files, output directories, and an optional `config/typescript.js|ts` file that controls automatic type generation in JavaScript projects and opts in to strict types. This documentation explains which folders store compiled code and how to toggle these features.
</Tldr>

[TypeScript](/cms/typescript)-enabled Strapi projects have a specific project structure and handle TypeScript project configuration through [`tsconfig.json` files](#project-structure-and-typescript-specific-configuration-files).

Strapi also has dedicated TypeScript features that are configured [in the `config/typescript.js|ts` file](#strapi-specific-configuration-for-typescript).

## Project structure and TypeScript-specific configuration files

TypeScript-enabled Strapi applications have a specific [project structure](/cms/project-structure) with the following dedicated folders and configuration files:

| TypeScript-specific directories and files | Location         | Purpose                                                                                                                                          |
| ----------------------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `./dist` directory                        | application root | Adds the location for compiling the project JavaScript source code.                                                                              |
| `build` directory                         | `./dist`         | Contains the compiled administration panel JavaScript source code. The directory is created on the first `yarn build` or `npm run build` command |
| `tsconfig.json` file                      | application root | Manages TypeScript compilation for the server.                                                                                                   |
| `tsconfig.json` file                      | `./src/admin/`   | Manages TypeScript compilation for the admin panel.                                                                                              |

## Strapi-specific configuration for TypeScript

Types generated by Strapi are based on the user project structure. Once the type definitions are emitted into their dedicated files, Strapi reads the type definitions to adapt the autocompletion results accordingly.

TypeScript projects (projects with a `tsconfig.json` file at the root) always generate types each time `strapi develop` starts or restarts the server. JavaScript projects do the same unless automatic type generation is disabled. `strapi start` never generates types, and `strapi ts:generate-types` always does.

The optional `config/typescript.js|ts` configuration file accepts the following parameters. New TypeScript projects include a `config/typescript.ts` file with `strictTypes: false`.

| Parameter | Description | Type | Required | Default |
| --- | --- | --- | --- | --- |
| `autogenerate` | Enable or disable automatic types generation when running `strapi develop` (JavaScript projects only).<br/><br/>🚧 This setting is considered experimental and might have issues or break some features. | `Boolean` | No | `true` |
| `strictTypes` <BetaBadge /> | Opt in to [strict types](/cms/typescript/strict-types) (TypeScript projects). Type generation then also writes the strict files in `types/generated/`, and TypeScript checks server lookups, documents, and typed route configurations against registered contracts.<br/><br/>Unset or `false` keeps the default types, and the next type generation removes the strict files. A value that is not a boolean fails type generation. Runtime behavior is the same in both cases. | `Boolean` | No | `false` |
| `licensedFeatures` <BetaBadge /> | The [licensed features](/cms/typescript/strict-types#licensed-features) the application builds against, for instance `['review-workflows', 'cms-content-releases']`, or `['licensed']` for a license with no feature. Contracts gated by a listed feature are typed, the others are `undefined`. List the features of the license the application runs with. The types cannot verify that license.<br/><br/>Only read when `strictTypes` is `true`. | `String[]` | No | `[]` |

The following example disables automatic type generation in a JavaScript project and turns strict types on in a TypeScript project:

<Tabs groupId="js-ts">
<TabItem value="js" label="JavaScript" default>

```js title="/config/typescript.js"
module.exports = ({ env }) => ({
  autogenerate: false,
});
```

</TabItem>
<TabItem value="ts" label="TypeScript">

```ts title="/config/typescript.ts"
import type { Core } from '@strapi/strapi';

const config: Core.Config.TypeScript = {
  strictTypes: true,
  // With a license, list its features:
  // licensedFeatures: ['review-workflows'],
};

export default config;
```

</TabItem>
</Tabs>
